🏛️ 6.1 Basics of Data Warehousing

Definition

Definition (W.H. Inmon) A Data Warehouse is a subject-oriented, integrated, time-variant, and non-volatile collection of data in support of management's decision-making process.
  • Subject-oriented: Organised around major subjects (customers, sales, products), not applications.
  • Integrated: Data from disparate sources is cleaned and unified.
  • Time-variant: Contains historical data — every key contains a time element.
  • Non-volatile: Data is not updated or deleted — only loaded and read.

Operational DB vs. Data Warehouse

Feature Operational DB (OLTP) Data Warehouse (OLAP)
Purpose Day-to-day operations Decision support & analysis
Data Current, detailed Historical, summarized
Operations INSERT, UPDATE, DELETE Mostly SELECT (read-only)
Schema Normalized (3NF) Denormalized (Star/Snowflake)
Users Clerks, tellers, front-end Analysts, managers, executives
Query size Short, simple transactions Complex, long-running queries
Size 100 MB – 10 GB 100 GB – Terabytes

Characteristics of a Data Warehouse

  • Stores large amounts of historical data.
  • Supports complex analytical and ad-hoc queries.
  • Contains data integrated from multiple heterogeneous sources.
  • Data is consistent with standardized formats and definitions.
  • Provides a single version of the truth for the organization.

Functions of a Data Warehouse

  • Data consolidation: Gather data from disparate operational systems.
  • Data transformation: Standardize formats, resolve inconsistencies.
  • Historical storage: Maintain years or decades of data for trend analysis.
  • Query support: Serve complex analytical queries efficiently using OLAP cubes.
  • Report generation: Provide dashboards, reports, and KPIs to decision-makers.

Advantages of Data Warehousing

  • Improved business intelligence and decision-making.
  • Single, unified view of organizational data.
  • Historical analysis and trend identification.
  • Improved query performance (separate from OLTP systems).
  • Data quality improvement through ETL processes.
  • Enables data mining and predictive analytics.

Disadvantages

  • High initial cost of setup and maintenance.
  • Complex ETL processes for data loading.
  • Data latency — not real-time (batch updates).
  • Requires skilled personnel and ongoing administration.
  • Flexibility issues when source systems change.

Applications

  • Retail: Sales trend analysis, inventory management, customer segmentation.
  • Healthcare: Patient outcome tracking, resource utilization analysis.
  • Finance: Risk analysis, regulatory reporting, fraud detection.
  • Telecommunications: Call detail records analysis, churn prediction.
  • Government: Tax analysis, budget planning, public service optimization.
A retail chain uses its data warehouse to analyze five years of sales data, identifying that umbrella sales spike in coastal cities three weeks before monsoon season — enabling proactive stocking.

🏗️ 6.2 Architecture of Data Warehousing

Multitier Architecture

The most common data warehouse architecture uses a three-tier design:

  1. Bottom Tier (Data Sources & ETL Layer):
    Operational databases, external data sources, flat files → data extracted, transformed, and loaded into the warehouse.
  2. Middle Tier (Data Warehouse Server):
    The central warehouse stores the integrated, cleaned, historical data. OLAP server sits here.
  3. Top Tier (Frontend / Client Layer):
    Query and reporting tools, dashboards, data mining tools, and OLAP clients used by end-users.
Tier 1: Sales, HR, and Finance OLTP databases → ETL → Tier 2: Enterprise Data Warehouse → Tier 3: BI dashboards and Excel pivot tables.

Stages of Data Warehousing

  1. Data Sourcing: Identify and connect to source systems.
  2. Data Staging: Temporary area where raw extracted data is held before transformation.
  3. Data Integration (ETL): Transform, clean, and load data into the warehouse.
  4. Data Storage: Persist data in the central warehouse with appropriate schemas.
  5. Data Access & Analysis: End users query via OLAP or BI tools.
  6. Data Presentation: Reports, dashboards, visualizations delivered to stakeholders.

Data Warehouse Models

Enterprise Data Warehouse (EDW)

A centralized warehouse that integrates all enterprise-wide data across all departments and subjects.

  • Single source of truth for the entire organization.
  • High initial cost and complexity.
  • Best for large organizations needing consistent cross-departmental reporting.
A bank's EDW contains customer, loan, transaction, and branch data from all regional offices under one schema.

Data Mart

Definition A data mart is a subset of a data warehouse that focuses on a specific business area or department (e.g., marketing, sales, HR).
  • Dependent data mart: Derived from the enterprise data warehouse.
  • Independent data mart: Created directly from source data, without an EDW.
  • Faster to implement and lower cost than an EDW.
  • Allows departments to have tailored data structures and access control.
The Marketing department's data mart contains only customer demographics, campaign results, and purchase history — irrelevant HR or finance data is excluded.

Virtual Warehouse

Definition A virtual warehouse provides views over operational databases — no physical data is copied to a central store; data is queried on-demand from source systems.
  • Low storage cost — no data duplication.
  • Data is always current (real-time).
  • Performance bottleneck on source systems for complex queries.
  • Less scalable than physical warehouses.
A virtual data warehouse queries three live databases simultaneously when a report is run, presenting the results as if from one unified source.

ETL Process (Extract, Transform, Load)

Definition ETL is the process of extracting data from source systems, transforming it into a consistent format, and loading it into the data warehouse.

Extract

  • Pull data from OLTP databases, flat files, APIs, or external sources.
  • Full extraction or incremental extraction (changed data only).
  • Data is staged in a temporary landing area.

Transform

  • Cleaning: Handle missing values, fix data type issues, remove duplicates.
  • Standardization: Unify date formats, currency units, name conventions.
  • Enrichment: Derive new attributes (e.g., calculate age from date of birth).
  • Business rules: Apply domain-specific transformations and validations.
  • Aggregation: Summarize data (daily → monthly totals).

Load

  • Initial (full) load: First-time load of all historical data.
  • Incremental load: Subsequent periodic loads of new/changed data.
  • Slowly Changing Dimensions (SCD): Strategies for handling attribute changes over time (Type 1: overwrite, Type 2: add new row, Type 3: add new column).
ETL job runs nightly: Extract yesterday's sales from 50 retail POS systems → Transform currencies, standardize product codes → Load into the Sales fact table in the warehouse.

Metadata Repository

Definition Metadata is "data about data". The metadata repository stores all descriptive information about the data warehouse and its contents.

Types of Metadata

  • Technical metadata: Schema definitions, data lineage, ETL mappings, data types, table structures.
  • Business metadata: Business definitions of data elements, ownership, business rules, KPI definitions.
  • Operational metadata: ETL job logs, last refresh times, data volumes, error logs.

Functions of Metadata Repository

  • Enables users to understand what data is available and what it means.
  • Tracks data lineage — where did this data come from and how was it transformed?
  • Supports impact analysis — what reports break if we change this attribute?
  • Improves governance and compliance by documenting data policies.
An analyst queries the metadata repository to find out that the "Revenue" field in the Sales mart is calculated as (Quantity × UnitPrice − Discount), sourced from the ERP system's order table.
